# CZK Cpi Forecasting - Latest models

## The current paths are connected

The new command `python -m tools.current_path.run` calculates the independent nowcast and the three current monthly paths from one captured information set. It saves input frames, code/static-source copies, runtime identity, monthly and annual forecasts, component contributions and readiness checks. Eligible runs are recorded in the archive, one bundle per path model, and an offline chart is produced automatically.

The old `forecast_independent.py --path` command remains the legacy bridge. Use the new command for the current roster. The legacy code and frozen results were preserved so their historical replays remain meaningful.

| Display name | Exact model ID | Core forecast |
|---|---|---|
| FAST core trend | STATE_FAST_R15 | Changing local core trend plus a mean-reverting residual |
| Current core trend | STABLE_LOCAL_CORE_R14B | Trailing twelve-month mean of log core changes, with destination-month seasonality |
| Gentle core slope | DAMPED_P95_Q001_R16 | The existing fixed p95_q001 damped-slope filter |

All three use HARD_BASE at h0. They share the stable food pipeline, constant-pump fuel assumption, administered-price announcements, alcohol/tobacco forecast, released basket weights and reconciliation wedge. Consensus and CNB forecasts do not enter these paths. Sentiment remains an optional nowcast comparison produced by the existing engine; it does not enter the archived HARD_BASE anchor.

## What was verified

The new shared function was rerun for all **90 origins**, with the original HARD_BASE anchor supplied at each origin. All **3,510 model/horizon forecasts** matched the canonical research results. The comparison covers h0–h12 monthly forecasts, compounded YoY forecasts, future block values, weights and contributions. There were **zero missing-value discrepancies**, and the maximum numerical difference was **5.329×10⁻¹⁵ percentage points**. The test also now rejects incomplete annual reference coverage.

This verifies the path migration conditional on the original h0 anchors. It is not a fresh 90-origin rerun of the nowcast forest under the changed R19 runtime. The combined end-to-end July fixture did rerun the nowcast, including its six saved independent/sentiment points, then all 39 path rows. Its offline replay matched points, contributions, diagnostics and readiness at 1e-10 tolerance. A reviewer repeated that replay with HTTP/socket access blocked.

**191 tests passed** across the integration/regression and input-packaging checks. Two independent reviews covered the shared formulas and the live capture/recording boundary. They found four defects during development, which were corrected:

- Annual parity could silently skip missing reference rows. It now requires the complete reference horizon/model set.
- Food freshness checked the newest level rather than the newest usable monthly change. It now requires both consecutive endpoints to be finite and released.
- Input files were initially hashed and then reopened for parsing. They are now parsed directly from the exact verified bytes.
- Recording timestamps needed explicit validity and ordering checks, including rejection of `NaT`. These checks now precede archive issuance.

These fixes improve reliability. **They do not improve a historical RMSE or establish new forecasting skill.** The original R18 model-selection conclusions remain unchanged.

## Run and replay

From this repository, in the numerical runtime recorded in the snapshot:

```powershell
python -m tools.current_path.run --fixture --target 2026-07 --as-of 2026-08-04T23:59:00+02:00
python -m tools.current_path.run --replay output/research_r20/runs_final/20260915T082214Z_e1d40da2
```

Each capture gets a new directory. The command does not overwrite a prior forecast. Default capture and archive locations are `output/current_runs/` and `output/current_path_archive/`; override with `--output` and `--archive-root`. A replay checks the saved source/runtime identity, so later changes require restoration of the saved version instead of silently rerunning another model. Source copies are under the capture's `sources/` directory.

For a genuinely new forecast:

```powershell
python -m tools.current_path.run --live --target YYYY-MM --path-inputs PATH_TO_REFRESHED_INPUT_BUNDLE
```

Live mode uses the actual capture clock. It requires an explicit input bundle, finite complete paths, fresh required observations and a sourced first-release calendar entry. A failed readiness check cannot create a prospective archive record. Fixtures are always recorded as historical replays. The local archive supplies integrity checks, not a trusted external timestamp or original-vintage certification.

## Path input bundle

Prepare the following files, with the same definitions used by the research model. Package them with:

```powershell
python -m tools.current_path.seal_inputs --source PATH_TO_PREPARED_CSVS --output NEW_DATED_BUNDLE --source-notes "Sources, retrieval dates and release rules used"
```

The packaging helper copies and hashes supplied files. **It does not download or refresh them.** The live runner continues to obtain its nowcast frames from the existing `live_frames` loader; that loader also does not promise universal upstream refresh. Both input streams must be maintained.

| File | Exact contents |
|---|---|
| pipeline_log_levels.csv | Monthly `period` index; columns `agri4,food_ppi,food`, in 100 log-level points on a consistent base. `agri4` is the existing equal-weight average of rebased log prices for food wheat, cow milk, slaughter pigs and chickens. `food_ppi` is the declared national food-products producer-price level. `food` chains the model's monthly food CPI. |
| pipeline_available_from.csv | The same monthly index and three columns, containing each level's publication date/time. Preserve conservative release rules or recorded publication dates; do not replace them with reference-month dates. |
| pump_weekly.csv | Chronological unique observation Mondays. Retain the prepared gross/net petrol95 and diesel columns in CZK/litre, and the existing VAT/excise fields if supplied. Constant-pump calculation uses gross prices and the original seven-day availability convention. |
| manifest.json | Created by the packaging helper: schema, explicit units, source notes, capture timestamp and hashes for the three CSVs. |

The current prepared research food inputs stop at July 2026; pump data stop at 31 August. These are reference periods, not proof of current completeness. The frozen CPI release calendar stops at the August target. In particular, a September target presently fails the explicit-calendar check. No September live issuance was made in this integration batch.

## Assessment and next improvement

The gap between the models shown in research charts and the executable forecasting command is now closed for this three-model roster. There is no need to choose a new winner during deployment: retain FAST as the main research path and show current-core/gentle-slope as comparisons, under the existing R18 assessment. The model spread is not a calibrated confidence interval.

The next operational step is a sourced calendar/data refresh and the first actual dated forecasts. Before moving computers, pin and validate the full deployment runtime; R19's small HALF/FULL runtime differences remain relevant. This batch does not create a complete cross-platform environment installer.

For additional predictive skill, the strongest concrete research question remains the common noncore path: household energy repricing/expiry exposure and economically justified fuel scenarios. Test those as named challengers on the same fixed origins and horizons, preserve the current baseline, and evaluate live revisions as new information arrives. The existing failed food/probability experiments should not be silently reinstated. None of those new accuracy experiments was run here.
