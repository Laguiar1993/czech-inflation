## Findings and fixes made by root during review

### P1 — replay comparison accepted NaN mismatches (fixed)

The original comparison used `abs(actual − expected) > tolerance`. For NaN, that condition is false. A failed recomputation could therefore be printed as matched against a finite saved forecast; it also did not require the same set of point names.

Root added `verify_points`, which requires matching names and finite values on both sides before tolerance comparison. Tests now cover NaN, infinity, missing names and changed values. An independent direct probe now raises `nonfinite replay point: x` for `{x: NaN}` against `{x: 0.2}`.

Root also added runtime identity (Python, numerical/statistical package versions and X13 binary hash), a receipt for `forecast.json` and `snapshot.json`, completion timing and prospective eligibility. A result generated after the first release cannot become prospective evidence merely because its nominal input cutoff was earlier.

### P1 — a missing latest regulated observation remained ready (fixed)

At the valid July-2026 release eve, `2026-08-04T23:59:00+02:00`, the complete fixture was ready. Removing only June's regulated-price observation changed `HARD_BASE` by **+0.004859866 pp**, yet the original result still had `ready_for_first_release=True`, no missing-input entries and headline edge gap zero. Feature-cell and headline-edge checks alone did not expose the stale administered history.

Root added per-component history edges for core, regulated, food, official fuel and alcohol/tobacco; all required edges must be current for readiness. Weekly fuel's observed versus due edge and its model diagnostics are now returned too. A new regression verifies that missing June regulated data yields a one-month gap. The full-fixture probe was then rerun independently: it now returns readiness **False**, regulated edge **2026-05**, gap **1**, with fuel diagnostics present. This closes the demonstrated readiness omission without changing the numerical model.

### P2 — explicit false-alarm statistics were missing (added)

The original event table contained `alert`, `big`, direction and loss/gain fields, but the score table did not state false alarms or precision/recall. Root has added those columns.

The definition must be read literally: an alert is an absolute deviation from consensus of at least 0.2 pp; a big realized surprise is at least 0.4 pp. A false alarm is an alert without a big realized surprise. This is not the same as a money-losing trade or even a worse forecast; material error wins/losses remain a separate measure.

Independent counts from the existing 90-row event output:

| Model | Alerts | Big surprises caught | False alarms | Big surprises missed | Alert material losses versus consensus |
| --- | ---: | ---: | ---: | ---: | ---: |
| HARD_BASE | 20 | 7 | 13 | 16 | 8 |
| HARD_HALF | 22 | 7 | 15 | 16 | 9 |
| HARD_FULL | 23 | 7 | 16 | 16 | 10 |

All three catch 7 of the 23 big surprises. Precision is 35.0%, 31.8% and 30.4%, respectively; recall is 30.4%. These are descriptive historical figures, not calibrated trading probabilities. In an `alerts`-only score slice, recall conditions on already having alerted; use the `all` or a prespecified calendar frame for an unconditional recall claim.

### P2 — quarter completeness should require finite values (fixed)

At inspection, `complete_quarters` used `values.notna().all()`. A read-only probe with monthly rates `[1, infinity, 3]` returned an infinite quarter instead of omitting/rejecting it. Root replaced this with a finite-value check. The normal known-month join and incomplete-final-quarter arithmetic are correct; the added condition closes this numerical-input safeguard.
