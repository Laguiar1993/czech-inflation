# Historical unemployment inputs — 9 September 2026

The delivered archive contains **103 of 103 monthly CZSO releases for reference
months January 2018–July 2026**, with **42,584 observations across vintages**.
Each release's table contains its then-published history from January 1993.
The first eligible origin is 1 March 2018 at 23:00 UTC. This covers 2019–2026
evaluation origins, including Covid and the 2024 window. It does **not** establish
real-time unemployment inputs for forecast origins during the 2008 crisis.
Earlier observations may be used to estimate a model at a later covered origin;
that is different from claiming they were available in their current form in 2008.

## Delivered artifacts and reproducibility

- `data/vintages/unemployment.csv.gz`: historical releases, with series,
  reference_period, available_from, value, source, sha256, adjustment,
  vintage_kind, release_date, reference_release, availability_precision,
  release_source, release_page_sha256 and raw_file.
- `data/vintages/manifest.json`: coverage and per-release publication evidence,
  table descriptions, source URLs, raw paths and SHA-256 hashes.
- `data/vintages/raw/`: 103 source HTML pages, 119 original XLSX rate tables,
  and the official methodology page. Approximately 25 MB including normalized
  artifacts; data and paths are portable and require no access to the local DB.
- `data/vintages/unemployment_latest_snapshot.csv`: the July 2026 release only,
  explicitly tagged `latest_vintage_snapshot`, retaining its real publication
  timestamp. This comparison file contains NSA and trend-cycle as distinct series.
- `data/vintages/source_notes.json`: methodology and artifact hashes, import-cache
  metadata, and the discovered earlier 2013 release alias.

From the repository, recover or reuse the originals with:

```text
python -m tools.archive_unemployment --start 2018-01 --end 2026-07
python -m tools.archive_unemployment --offline
python -m pytest test_vintages_r9.py -q
```

The downloader needs `requests`, `beautifulsoup4`, `openpyxl`, pandas and NumPy.
The historical selector itself needs only pandas and NumPy. Existing archived
bytes are reused; an offline rebuild needs no website or database. Missing pages
or attachments are recorded as unavailable, without invented values. The
normalized historical CSV and release manifest are regenerated by the command;
the separately tagged latest snapshot and source notes are retained audit outputs.

## Timestamp and vintage contract

```python
from data.vintages import released_unemployment

u = released_unemployment("2019-03-10T23:00:00Z")
# Optional: adjustment="sa", "trend_cycle", or "nsa".
# Default: adjustment="published_adjusted".
# u is a percentage-valued Series with a monthly PeriodIndex.
# u.attrs contains the selected rows' provenance and adjustment labels.
```

`select_vintages(frame, as_of, series=None)` requires an explicit timezone-aware
origin and timestamp on every row. It selects the last eligible vintage for each
series and reference month, including exact timestamp equality. Missing metadata,
nonfinite observations, noncanonical reference months, malformed digests and
duplicate vintage keys fail. Equivalent UTC timestamps cannot be disambiguated
by input order. The dedicated unemployment API also rejects rows tagged as a
latest-only snapshot.

The archived pages report publication **dates**, without a verified release hour.
Eligibility is therefore conservatively set to **the next calendar midnight in
Europe/Prague**, converted to UTC, with
`availability_precision=date_only_next_local_midnight`. This excludes the whole
release day rather than assume an intraday history. The timestamp is not an
inference from the reference month or a contemporary publication calendar. If
historical release-hour evidence is recovered later, it can refine this policy.

Recovered archives were downloaded in September 2026 from official release pages.
Their page publication dates and attached version-1 files provide archival
provenance; the hashes freeze the bytes recovered now. They do not prove the
website never silently replaced a historical attachment. The parser checks that
each attached table ends at its claimed reference month, has a contiguous history,
and identifies the total unemployment rate for ages 15–64 in its header. A current
2026 table accidentally attached to a 2019 release is rejected.

No artificial lag can turn the database's July 2026 unemployment vintage into a
2019 vintage. Read-only inspection confirmed both DB adjustment groups contain
January 1993–July 2026 history but only one release date, 31 August 2026. Its
primary key is reference month/adjustment/series/gender, which cannot retain
multiple historical releases for the same observation.

## Adjustment concepts and coverage

| Series | Releases | Observations across vintages | First eligible timestamp UTC | Last reference month |
|---|---:|---:|---|---|
| unemployment_sa | 87 | 29,928 | 2018-03-01 23:00 | 2025-03 |
| unemployment_trend_cycle | 16 | 6,328 | 2025-06-02 22:00 | 2026-07 |
| unemployment_nsa | 16 | 6,328 | 2025-06-02 22:00 | 2026-07 |

CZSO changed its monthly presentation with the **2 June 2025 release**, covering
**April 2025**, replacing the seasonally adjusted headline with trend-cycle.
It also began publishing the original unadjusted monthly rates alongside the
smoothed series. The older attachment 2 contains adjusted person counts, so it
cannot be reinterpreted as an unadjusted rate. These choices follow the official
[methodology announcement](https://statistikaamy.csu.gov.cz/jak-ocistit-nezamestnanost).

`published_adjusted` uses the latest actually published adjusted observation at
each origin. A 2019 origin therefore fits on a 2019 SA table's whole history; a
2026 origin legitimately fits on its revised trend-cycle history. Adjustment
labels are retained in the returned provenance. This policy follows publication
practice and is **not a homogeneous SA measure across all origins**. It should be
labelled accordingly in path comparisons. A strictly homogeneous NSA experiment
starts only in June 2025; its historical reference values are available for fitting
then, but are never backdated to earlier forecast origins. Any seasonal adjustment,
trend extraction or gap estimation applied to NSA must be fitted separately using
only the data selected at that origin.

The full-history revision mechanism is observable in the archive:

| Origin UTC | Selected adjustment | January 2019 unemployment (%) |
|---|---|---:|
| 2019-03-10 23:00 | SA | 2.1569603298 |
| 2024-03-10 23:00 | SA | 2.0858825036 |
| 2026-09-09 00:00 | Trend-cycle | 2.0707790226 |

The [January 2019 release](https://csu.gov.cz/rychle-informace/miry-zamestnanosti-nezamestnanosti-a-ekonomicke-aktivity-leden-2019),
[January 2024 release](https://csu.gov.cz/rychle-informace/miry-zamestnanosti-nezamestnanosti-a-ekonomicke-aktivity-leden-2024)
and [July 2026 release](https://csu.gov.cz/rychle-informace/miry-zamestnanosti-nezamestnanosti-a-ekonomicke-aktivity-cervenec-2026)
and their preserved attachments support these observations.

The search also located an official
[January 2013 release](https://csu.gov.cz/rychle-informace/miry-zamestnanosti-nezamestnanosti-a-ekonomicke-aktivity-leden-2013-aivs0ix6s0).
It uses a legacy opaque suffix; earlier canonical URLs do not resolve consistently.
That isolated discovery is not included as a continuous archive. The delivered
coverage starts in 2018, and earlier origins remain unavailable. No original NSA
data or 2008 publication vintages have been fabricated.

An unemployment-vintage-corrected path using the current import cache is still a
**mixed-vintage research experiment**, not a fully real-time experiment. Report
that limitation separately from correction of the unemployment leak. Household
LFS observations are observed economic statistics; their survey origin does not
make them forecast expectations.

## Verification

The selector and parser tests were written first and observed failing before
implementation. The final suite contains 27 checks, including future-revision
exclusion, most-recent eligible selection, exact timezone boundaries, missing
metadata, duplicate ambiguity, old reference values in a recent release, the
adjustment transition, missing NSA coverage, future rows in an archival table,
and raw-file hash/path integrity for all delivered releases. The offline rebuild
successfully regenerated all 103 releases from the retained XLSX and HTML files.

No model, live calculation, original database or original checkout was changed
by this work. The archive and input API are intended for root integration and
explicitly labelled path evaluations.
